# gnpctl Go port Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Behavior-identical Go port of the Python `../gnpctl`.

**Architecture:** One `internal/` package per Python module group; cobra CLI in `cmd/gnpctl`. Same SQLite schema, catalog tree, config and rendered output as Python. Parity gated by golden files produced from the Python version.

**Tech Stack:** Go (`export PATH=$HOME/.go/bin:$PATH`), cobra, yaml.v3, modernc.org/sqlite, openconfig/gnmi + grpc, net/http, log/slog.

**Spec:** `openspec/changes/port-to-go/{proposal,design}.md` and `specs/*/spec.md` (the contract). Python source `../gnpctl/gnpctl/*.py` is the behavioral reference; read the matching file before writing each task.

## Global Constraints

- Module `github.com/fatred/gnpctl-v2`; binary `gnpctl`; CGO off (`CGO_ENABLED=0 go build ./...` must pass).
- Error strings, CLI output lines and exit codes identical to Python (see `docs/`-less reference: `../gnpctl/docs/reference/cli.md`).
- SQLite schema per `../gnpctl/docs/reference/data-model.md`; WAL; `mod_<name>` columns with hyphen->underscore, additive `ALTER TABLE`.
- `capabilities_hash` identical to Python (`capabilities.py`).
- Render YAML key order identical to Python (`sort_keys=False`).
- Secrets never stored or logged: `credential_ref` is an env-var *name*.
- No new CLI flags, config keys or catalog content. No cgo. No dependency beyond Tech Stack without asking.
- Conventional Commits; signed; one task = one branch `task/<n>-<slug>` in its own worktree (`git worktree add ../gnpctl-v2-wt/<n> -b task/<n>-<slug> feat/port-to-go`), merged `--no-ff` into `feat/port-to-go` by the controller.

## Review Focus

- Existing Python-written DB opened by Go (extra/missing `mod_*` columns, NULL vs 0 defaults) -> must not error, must self-heal.
- Catalog with a vendor lacking `yang/` facts, or version strings like `25.3.2-rc1` / `4.32.0F` -> same release selection as Python `_version_key`.
- Target with no `catalog_key`, unreachable device, or gNMI timeout -> `last_error` set, `discovered` untouched, run continues, non-zero exit.
- `inventory pull` when one source errors and another succeeds -> successful source still synced, exit non-zero.
- `render` with the `render` config block absent -> clean error, nothing written; with zero discovered targets -> same files as Python.
